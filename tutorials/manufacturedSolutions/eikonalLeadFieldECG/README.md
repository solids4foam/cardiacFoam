# Eikonal lead-field ECG

This variant runs the existing [eikonal manufactured cube](../eikonalECG/README.md)
with both `eikonalECG` (the analytical pseudo-ECG kernel) and
`eikonalLeadFieldECG` (imported reciprocal sensitivities). `Allrun` copies the
maintained cube into `localCase`; it changes no inputs in the original case.
The default is a 40³ Cartesian mesh, with six MPI ranks when `parallel` is used.

```bash
./Allrun parallel
./Allclean
./Allrun -N 80
```

The existing cube options are forwarded to its maintained `Allrun`. This
variant requires 3D and always enables the lead-field observer. The original
cube also supports `./Allrun -N 40 -leadFieldECG yes` directly; its existing
20³ pseudo-ECG regression and references remain unchanged.

## Source and recording

The source solver computes `tau`, with manufactured exact activation time
`tau = exp(x+y+z)` on the unit cube. Both observers use the spatially uniform
voltage template `U(s) = sin(2*pi*s)` volts and reconstruct
`grad(Vm) = -U'(t-tau)*grad(tau)`. They record 201 common sample times from
0 to 2 seconds. The activation-time solve is steady; ECG sampling is a
post-solve observation, independent of a propagation time step.

For this verification only, `setManufacturedLeadFields -eikonal` prescribes
`L_positive = (1,2,3)` and `L_negative = -(1,2,3)` in m⁻². These are synthetic
sensitivity fields, not torso fields generated by `buildLeadFields`. The
import, provenance and physical-conductivity contracts are exercised, but
this case does not verify the reciprocal conductor solve.

The lead-field observer computes `sum(Vcell * Lcell . grad(Vm)cell)`. Its
independent reference uses the divergence theorem: for constant `L`, the
volume integral is a sum of face voltage differences. Symmetry gives

```text
y_positive(t) = 6 int_0^1 int_0^1
    [sin(2*pi*(t-exp(1+a+b))) - sin(2*pi*(t-exp(a+b)))] da db.
y_negative(t) = -y_positive(t).
```

The C++ verifier uses Gauss-Legendre orders 64 and 96 on these faces. A
separate Python check uses order 80 and checks the written reference,
channel signs, sampling times, normalized errors and source/gradient bounds. Each observer has its
own reference; the two numerical ECGs are different functionals.

The rapid phase variation near the upper corner makes 20³ insufficient for
this particular constant-sensitivity integral. The 40³ default resolves it
much better. This resolution choice is not a claimed convergence order.

## Template and state controls

Before the PDE run, the fixture utility exercises the production observer
with affine activation time, exact fixed-value boundaries, a deliberately
stale source gradient and a provider exposing no `Vm`. Four checks cover the
manufactured, endo, mid and epi templates. An independent interval scan of
the compiled tables checks the piecewise-linear derivative and mV-to-V
conversion. The utility also checks unchanged activation values, boundaries,
source gradient cache and repeated-solve values.

The regression checks rejection of regional templates, unknown template
names and invalid sampling intervals. Regional and personalized templates
remain available through the existing pseudo-ECG path; reciprocal eikonal
recording currently requires one spatially uniform template.

## Outputs

The top-level `postProcessing` link points to `localCase/postProcessing`:

- `eikonalLeadFieldECG.dat`: reciprocal observer traces in volts.
- `manufacturedEikonalLeadFieldECG_LeadField.dat`: traces, independent
  references, absolute errors and reference-quadrature differences.
- `eikonalECG.dat`: concurrent raw pseudo-ECG traces for the cube electrodes.
- `manufacturedEikonalECG_ECG.dat`: independent pseudo-ECG references/errors.
- `manufacturedEikonalActivationTime.dat`: activation and gradient errors.
- `eikonalDualECGSummary.json`: independent functional-error controls.

`Allclean` removes the private copy and output/log links. For production,
replace the synthetic sensitivities with fields constructed on the intended
heart/torso conductor and keep its `leadFieldProperties` and metadata.
