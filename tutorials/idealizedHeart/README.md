# Idealized heart

A shared idealized biventricular ellipsoid mesh, and everything built on
it: healthy electrophysiology, electromechanics, and pathology-injection
techniques. A simple, fast, reproducible testbed that's fully checked
into version control.

```text
idealizedHeart/
├── mesh/            the one committed geometry (heartTorso) and the Purkinje graphs
├── prepareHeartMesh  writes the heart mesh and its fields from mesh/heartTorso
├── electroHeart/     healthy EP baseline, 3 solver-combination variants
├── electroMechHeart/ sequential electromechanical coupling
├── idealizedTorso/   the bidomain heart in an idealized torso, body-surface ECG
└── pathos/          pathology-injection techniques (structural + ionic)
```

## `mesh/`

One committed geometry (Git LFS), supplied input, not generated by
`blockMesh`:

- `mesh/heartTorso/`: the idealized ventricles inside an idealized torso,
  a conformal tetrahedral mesh of 299,482 cells in five cell zones
  (`myocardium`, `blood`, `lungs`, `chestWall`, `torso`), with its fields in
  `0/` (`fiber`, `sheet`, `sheetNormal`, `tm`, `tv`, `t`, `apicobasal`,
  `Conductivity`, `bodyAndOrgansConductivity`). The four heart surfaces are
  kept as face zones (`EPIheart_EPICutFaceZone`, ...). `idealizedTorso`
  runs on it as it is.
- `mesh/constant/purkinjeGraph` and `purkinjeGraphPig`: the two Purkinje
  trees.

The heart cases (`electroHeart`, `electroMechHeart`, `pathos/*`) run on the
ventricles alone. `prepareHeartMesh`, which each of their `Allrun` scripts
calls first, writes them from `heartTorso` into `mesh/constant/polyMesh` and
`mesh/0/` (git-ignored, rewritten only when an input changes):

- the mesh is the `myocardium` cell zone (`subsetMesh`), with the patches
  `EPI`, `BASE`, `ENDO_LV` and `ENDO_RV` rebuilt from the face zones
  (`topoSet`, `createPatch`): 26,642 points, 123,617 cells;
- the fields `fiber`, `sheet`, `sheetNormal`, `tm`, `tv`, `apicobasal` and
  `Conductivity` are the first 123,617 entries of the `heartTorso` fields,
  copied as text, `zeroGradient` on every patch (`Conductivity`:
  `calculated`, the value of the face's cell).

`heartTorso` stores the heart cells and points first, in the order of the
heart mesh, so this is the heart mesh itself. Its points, faces, owner,
neighbour and boundary are identical, byte for byte, to the heart mesh this
directory used to commit, and so are the anatomy fields; `Conductivity`
carries the 12 significant digits of `heartTorso`. The only cell zone is
`myocardium` (with the empty torso zones and the four face zones). Raw
bounding box x:[0.0, 4.0] y:[-2.0, 3.0] z:[-2.0, 2.0], scaled uniformly by
`0.02` to adult-heart-scale SI metres.

## `electroHeart/`

Electrophysiology only, three solver combinations (`monodomain` default,
`eikonal`, `hybrid`) selected at run time — see its own README for the
full stack table and the numerical-stability notes the `eikonal` variant
needed. `monodomain` is the regression-covered variant.

## `electroMechHeart/`

Sequential electromechanical coupling (TNNP ionic model, Land-Niederer
active tension) on the same mesh — see its own README for mechanical
boundary conditions and calibration caveats.

## `idealizedTorso/`

The bidomain ventricles inside an idealized torso (blood, lungs, chest wall,
torso) on their own heart/torso mesh, `mesh/heartTorso` (Git LFS), over one
beat. The body-surface ECG comes from lead fields (`leadField`, one-way) or
from a `phiE` over the heart and the torso (`bath`, two-way), chosen at run
time. See its own README for the wall condition of each coupling and the
cost.

## `pathos/`

Two techniques for injecting a pathology into the model —
`conductionBlock` (structural: severs a Purkinje branch) and
`ionicPathology` (ionic: TNNP constant overrides) — see its own README.

## Regression

| Case | Tier |
| --- | --- |
| `electroHeart` | `full`: the three solver variants on the human tree |
| `electroMechHeart` | `full`, an expected skip in `lightweight` build mode |
| `pathos/conductionBlock` | `full`: `lbbb` and `rbbb` |
| `pathos/ionicPathology` | `none`: the solver is checked by `electroHeart`, the overrides by `../electrophysiologyProtocols/ionicHeterogeneity` |
| `idealizedTorso` | `none`: the couplings are checked by `manufacturedSolutions/bathBidomain/slab` and `manufacturedSolutions/leadFieldECG` |

`Alltest-regression` copies `mesh/heartTorso`, the Purkinje graphs and
`prepareHeartMesh` into the sweep once, for every `idealizedHeart` case.
